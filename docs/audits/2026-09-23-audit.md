# BrandLens Audit — 2026-09-23

Read-only audit (random-audit skill) of security, concurrency, reliability, accessibility and UI consistency. No code was modified.

**Scope:** all API routes, the job pipeline (`src/lib/jobs`), crawler, extractors, analysis/LLM calls, PDF/export, rate limiting, deploy config, and all client pages/components.
**Method:** end-to-end flow tracing (submit → crawl → extract → LLM → persist → poll → render/export/share), plus runnable proofs against the real modules (scripts in the session scratchpad: SSRF validator, robots parser, ReDoS timings, color parser, apex→www link filter). Contrast ratios computed from the Tailwind v4 oklch palette and `globals.css` tokens.

**Deployment context:** Railway (`railway.toml`, `Procfile`, `nixpacks.toml`, long-lived Node server) with an untracked `vercel.json` suggesting a move to Vercel. Findings flagged *(Vercel)* only apply after that move.

## HIGH

### Security

**A1. SSRF via redirects — validation runs once, redirects are never re-checked**
- Category: Security · Confidence: High Confidence (code path; not live-tested)
- Location: `src/app/api/analyze/route.ts:43` (only call to `validateUrl`), `src/lib/crawler/cheerio.ts:53-61` (`redirect: 'follow'`), `src/lib/crawler/playwright.ts:189-192` (`page.goto`), `src/lib/crawler/robots.ts:36`, `src/lib/crawler/index.ts:49`
- Issue: A public host that passes validation can 302 to `http://169.254.169.254/…`, `http://127.0.0.1:port/`, `http://10.x/`. Both undici and Chromium follow https→http downgrades. The final URL is never checked.
- Impact: Internal/metadata requests. Internal page titles, headings and text flow into LLM prompts, SEO evidence and the **public shareable report**, so data can be read back.
- Repro: Submit `https://attacker.tld/`, where `/` returns `302 Location: http://169.254.169.254/latest/meta-data/`.
- Fix: One `safeFetch` guard for every outbound request. Use `redirect: 'manual'` and re-validate each hop (max 5). Resolve DNS and reject private ranges. Pin the connection to the vetted IP with an undici `Agent` + `connect.lookup`. In Playwright, a `page.route('**/*')` applies the same check to every request.

**A2. SSRF validator is string-only: DNS names resolving to private IPs and several reserved ranges pass**
- Category: Security · Confidence: **Confirmed**
- Location: `src/lib/utils/url.ts:6-26, 113-164, 169-215`
- Evidence (validator output):
  - Allowed: `foo.localhost`, `localtest.me`, `localhost.` (all resolve to loopback), `100.100.100.200` (Alibaba metadata / CGNAT), `100.64.0.1`, `198.18.0.1`, `example.com:6379`.
  - Blocked only by accident, via the "no dot = internal" rule: IPv6 forms like `[::ffff:7f00:1]` and `[64:ff9b::a9fe:a9fe]`. The IPv6 branch at `:127` is effectively dead code.
  - No DNS resolution means DNS rebinding also works.
- Fix: Resolve A/AAAA and check every address with `ipaddr.js` (private, loopback, link-local, CGNAT, 198.18/15, multicast, reserved, IPv4-mapped v6), then connect to the checked IP (see A1). Restrict ports to 80/443.

**A3. Headless Chromium runs arbitrary site JS unsandboxed with no egress filter**
- Category: Security · Confidence: High Confidence
- Location: `src/lib/crawler/playwright.ts:24-32` (`--no-sandbox`, `--disable-setuid-sandbox`), `:140-144` (`ignoreHTTPSErrors: true`), `:179-186` (route filter by resource type only)
- Issue: Crawled pages run their JS on the server for 30s+. That JS can fetch internal IPs (blind SSRF), use DNS rebinding to read the responses back into the DOM (and therefore into the report), and run any renderer exploit with no sandbox.
- Fix: Apply the egress guard in `page.route`. Drop `--no-sandbox` and `ignoreHTTPSErrors`. Ideally run the crawl in an isolated, egress-restricted sandbox (e.g. Vercel Sandbox or a locked-down container).

**A4. Stored DOM XSS in the "Download Brand Board (PNG)" export**
- Category: Security · Confidence: **Confirmed** (source→sink traced)
- Location: `src/components/export-dropdown.tsx:50-100` (`container.innerHTML = \`…${report.brandName}…${font.name}…${trait}…\``)
- Evidence:
  - `font.name` comes from crawled `<link href="fonts.googleapis.com/css2?family=…">` through `decodeURIComponent` (`typographyExtractor.ts:330`), and from `@font-face` `font-family` (`:387`). Only quotes are stripped, so `<` and `>` survive.
  - `tone.traits` comes from Claude and can be steered by prompt injection from page text.
  - `color.hex`/`role` are also interpolated unescaped.
- Impact: A malicious site plants `family=%3Cimg%20src%3Dx%20onerror%3D…%3E`. Anyone who opens the shared `/analyze/[id]` link and clicks the export runs attacker JS on the BrandLens origin.
- Fix: Build the board with DOM APIs + `textContent`, or render a React node into the hidden container. Validate hex values with `/^#[0-9a-f]{3,8}$/i`.

**A5. Rate limiting is bypassable, so crawler, Chromium and Anthropic spend are unbounded**
- Category: Security / Race Condition · Confidence: Confirmed (logic) · XFF behaviour on Railway: Needs Verification
- Location: `src/app/api/analyze/route.ts:14-28, 66-87`, `src/lib/rate-limit.ts`, `src/app/api/rate-limit/route.ts:12-24`
- Issues:
  1. The key is the first `x-forwarded-for` value, which the client controls. If the proxy appends rather than overwrites, a random header each request gives unlimited analyses.
  2. `checkRateLimit()` and `recordUsage()` are separate, non-atomic steps. N concurrent POSTs all pass the check before any are recorded.
  3. Storage is a JSON file plus module memory. It resets on every deploy/restart and is per-instance (on Vercel, effectively no limit).
- Impact: Cost abuse (Anthropic: 4 calls per analysis) and CPU/memory exhaustion (Chromium).
- Fix: An atomic counter in Postgres (`INSERT … ON CONFLICT DO UPDATE … RETURNING count`) or Upstash Redis `INCR` + TTL. Take the IP from the platform-trusted source only. On Vercel that is `x-forwarded-for`, which Vercel overwrites; on Railway, use the last hop.

### Reliability

**A6. `pnpm start` runs `prisma db push --accept-data-loss` on every boot**
- Category: Reliability · Confidence: **Confirmed**
- Location: `package.json` `"start"`; used by `railway.toml`, `Procfile`, `nixpacks.toml`
- Impact: Any schema change (a rename, a type change, a removed field) silently **drops production columns/data** at the next deploy or restart. There is no migration history and no review step.
- Fix: Switch to `prisma migrate` with committed migrations. Run `prisma migrate deploy` as a release step, never with `--accept-data-loss`.

**A7. Background jobs are fire-and-forget; interrupted jobs are stuck forever**
- Category: Reliability · Confidence: Confirmed (code) / High (Vercel impact)
- Location: `src/app/api/analyze/route.ts:90` (`runAnalysis(...).catch(console.error)` after the response is sent), `src/lib/jobs/analyze.ts`
- Issue:
  - A restart, deploy or crash mid-run leaves the report in `crawling`/`analyzing` permanently. Nothing reaps it, and the client polls forever (see A12).
  - *(Vercel)* The function is frozen or terminated once the response is sent, so most jobs never finish. The `postinstall: playwright install chromium` flow also doesn't produce a usable Chromium in Vercel Functions.
- Fix:
  - Persist a `heartbeatAt`/`startedAt` column and mark jobs stale after a deadline (e.g. 5 min) as failed on read.
  - On Vercel, use `after()` at minimum, or better a durable Workflow/Queue step. Use `@sparticuz/chromium` or run the crawler in Vercel Sandbox.

**A8. ReDoS: hostile HTML freezes the Node event loop**
- Category: Performance / Security (DoS) · Confidence: **Confirmed** (measured)
- Location:
  - `src/lib/extractors/geo.ts:~521` (`fullAddressPattern`), `:398, :406`
  - `src/lib/extractors/social.ts:295` (`anchorPattern`)
  - `src/lib/extractors/logo.ts:95-101`
  - `src/lib/extractors/seo.ts:154`
- Evidence:
  - geo on a `/contact` URL: 22 KB → 2.8 s, 44 KB → **16 s** (super-quadratic).
  - social: 448 KB → 9.5 s.
  - logo: quadratic.
- Impact: Extraction runs synchronously in the web server process, so one 100–200 KB page stalls **every request** on the instance for minutes.
- Fix: Extract from cheerio text nodes instead of regexing raw HTML. Cap input (~50 KB per extractor). Remove overlapping quantifiers or use RE2. Move extraction to a worker thread with a timeout.

**A9. Unbounded `Crawl-delay` hangs a job indefinitely**
- Category: Reliability · Confidence: **Confirmed**
- Location: `src/lib/crawler/robots.ts:122-126`, `src/lib/crawler/index.ts:163-167`
- Evidence: `Crawl-delay: 86400` parses to `{ allowed: true, crawlDelay: 86400 }`, and `sleep()` then runs with the total timeout checked only at the loop top.
- Fix: Clamp the delay to ≤10 s and make every await honour a single job deadline (`AbortSignal.timeout`).

**A10. robots.txt: rules for *any* "…bot" UA are applied to BrandLens, and groups are misparsed**
- Category: Reliability (correctness) · Confidence: **Confirmed**
- Location: `src/lib/crawler/robots.ts:87-93` (`agent.includes('bot')`)
- Evidence:
  - `User-agent: GPTBot / Disallow: /` followed by `User-agent: * / Disallow: /admin` → `/` and `/about` both **blocked**.
  - Multi-UA groups (`*` + `Slurp`) lose their rules.
- Impact: The now-common "block AI crawlers" robots.txt makes those sites fail with "No pages could be crawled".
- Fix: Group-aware parsing: prefer the `brandlens` group, fall back to `*`, and never merge other bots' groups. Or use the `robots-parser` package.

**A11. Deprecated Anthropic model hardcoded; LLM output unvalidated and can crash the job**
- Category: Reliability · Confidence: High Confidence
- Location: `src/lib/analysis/tone-voice.ts:9`, `src/lib/analysis/generate-assets.ts:9` (`'claude-sonnet-4-20250514'`); parsing at `tone-voice.ts:168-185, 267-293, 469-482`, `generate-assets.ts:131-146`; unguarded uses at `generate-assets.ts:63-65`, `tone-voice.ts:402-421`, `consistency-score.ts:239`, `pdf/generator.tsx:279-320`
- Issues:
  - Sonnet 4 is deprecated. At retirement every call fails silently into heuristic fallbacks, and error text gets stored in public reports (A33).
  - Output is pulled out with `/\{[\s\S]*\}/` + `JSON.parse`. If `traits` comes back as a string, `.join`/`.map` throws outside `try`, so a full crawl is thrown away and the PDF route 500s.
- Fix:
  - One env-configurable model constant (`claude-sonnet-5` / `claude-opus-5-5`).
  - Structured outputs (JSON schema), or zod-validate every response.
  - Delimit untrusted page text in prompts, and clamp array and string sizes.

**A12. Analysis page: one failed poll permanently shows "Analysis Failed"; polls overlap and apply out of order; no timeout** *(also the current ESLint build error at `:80`)*
- Category: Race Condition / Reliability · Confidence: **Confirmed**
- Location: `src/app/analyze/[id]/page.tsx:52-90`
- Issues:
  - The `catch` sets `status='error'` and polling stops for good. Any blip or a non-JSON 502 shows as a failure while the job is still running.
  - `setInterval` has no in-flight guard, so a stale "crawling" response can land after "completed".
  - The effect depends on `status`, which restarts the interval on every change.
  - There is no max duration.
  - `react-hooks/set-state-in-effect` lint fails at `:80`.
- Fix: Recursive `setTimeout` scheduled after each response settles. Add an `AbortController` and a sequence number. Retry with backoff (3×) before showing an error. Keep status in a ref. Add a 5-min timeout with a "still working / retry" UI.

**A13. Compare page can be stuck on "Analyzing…" forever**
- Category: Race Condition / Reliability · Confidence: **Confirmed**
- Location: `src/app/compare/page.tsx:52-88`
- Issues:
  - `if (data.id)` has no else, so a 429 or 400 leaves the UI permanently disabled.
  - The poll has no try/catch (unhandled rejection).
  - The `setTimeout` chain is never cancelled on unmount.
  - Errors are shown with `alert()`.
- Fix: Handle `!ok` or a missing id inline with `role="alert"`, wrap each poll in try/catch, store the timer in a ref and clear it on unmount, and cap retries.

### Accessibility

**A17. The Export dropdown isn't an accessible menu**

**A18. URL inputs have no label; errors are neither announced nor linked**

**A19. The results header overflows on phones**

## MEDIUM

### Security / Race conditions

**A20. There's no ownership model: anyone can mutate any report they can find the ID for**
- Category: Security (IDOR) · Confidence: **Confirmed**
- Location: `src/app/api/report/[id]/publish/route.ts`, `src/app/api/report/[id]/regenerate-assets/route.ts`, `src/app/api/status/[id]/route.ts`
- Evidence: How report IDs leak:
  - `POST /api/analyze` for an already-cached domain returns the **existing** report's `id`.
  - The stored report JSON includes `id` and `slug`, so every status or public-report response exposes them.
- Impact: Anyone can flip any report public or private through `publish`, which no UI calls, so it is pure attack surface. Anyone can also overwrite the owner's marketing copy and spend its 3 regenerations (Anthropic cost).
- Fix: Delete the unused `publish` route. Issue a per-report capability token (an httpOnly cookie or secret returned only to the creator) that mutations require. Remove `id` from the public-report payload.

**A21. Concurrent submissions for the same domain start duplicate crawls**
- Category: Race Condition · Confidence: High Confidence
- Location: `src/app/api/analyze/route.ts:55-90`, `src/lib/jobs/analyze.ts:372-400`
- Issue: `getCachedReport` only matches `completed` reports. Two users or tabs (or double-submits) analysing the same domain each start a full crawl and each use up rate-limit budget.
- Fix: Return an in-flight report (`status NOT IN (failed)` and not stale) for the same domain. Enforce with a partial unique index or an advisory lock.

**A22. Regenerate-assets: TOCTOU on the limit, and the report blob is overwritten on write**
- Category: Race Condition · Confidence: High Confidence
- Location: `src/app/api/report/[id]/regenerate-assets/route.ts:18-78`
- Issue:
  - The count is checked, then an LLM call runs for about 10 s, then `count + 1` is written. Concurrent requests exceed the limit of 3.
  - Both requests read and rewrite the whole `data` JSON, so the last write wins.
- Fix: An atomic conditional increment (`updateMany where count < 3`) before the LLM call. Stop duplicating assets inside the `data` blob.

**A23. `/api/pdf/[id]` is an unauthenticated, uncached CPU amplifier**
- Category: Performance / Security (DoS) · Confidence: High Confidence
- Location: `src/app/api/pdf/[id]/route.ts`
- Issue: Every GET renders a full react-pdf document. There's no rate limit and no caching.
- Fix: Cache the rendered PDF (by report ID + `completedAt`) using Cache-Control/ETag or Blob storage, and rate-limit the route.

**A24. More SSRF through unvalidated stylesheet and sitemap fetches**
- Category: Security · Confidence: **Confirmed** (a sitemap entry pointing at `http://169.254.169.254/…` is accepted)
- Location: `src/lib/crawler/cheerio.ts:81-99, 186-197, 284`, `robots.ts:96-100`, `index.ts:47-51`
- Issue: Plain-http GETs go to any host, and the bodies are held in memory. HTTPS is not enforced on these paths.
- Fix: Route these through the same `safeFetch` (A1).

### Reliability

**A25. `page.evaluate` has no timeout and page JS can hijack it**
- Category: Reliability · Confidence: High Confidence
- Location: `src/lib/crawler/playwright.ts:206-512`
- Issue: The page can redefine `document.fonts.ready`, `getComputedStyle` and similar to hang the crawl forever or return made-up typography data.
- Fix: `Promise.race` against a deadline, and evaluate in an isolated world or through CDP.

**A26. Browser lifecycle: shared singleton, launch race, cross-job close, context leak**
- Category: Reliability · Confidence: High Confidence
- Location: `src/lib/crawler/playwright.ts:15-45, 140-146, 580-585`, `index.ts:100, 241`
- Issues:
  - Two concurrent launches can orphan a Chromium process.
  - One job's `closeBrowser()` kills another job's in-flight pages.
  - There's no `try/finally`.
  - If `newPage()` throws, the context leaks.
- Fix: Use a ref-counted browser with the launch promise as the lock, and close it in `try/finally`.

**A27. Response sizes are unbounded**
- Category: Performance · Confidence: High Confidence
- Location: `cheerio.ts:72, 95`, `robots.ts:50`, `index.ts:55`, `playwright.ts:509-536`
- Issue: Up to 25 pages and 250 CSS files are read fully into memory.
- Fix: Stream with byte caps (about 5 MB for HTML, 1 MB for CSS) and check `content-length` first.

**A28. Apex→www redirect drops all discovered links and sitemap entries**
- Category: Reliability (correctness) · Confidence: **Confirmed**
- Location: `cheerio.ts:161`, `index.ts:61, 223`, `utils/url.ts:100-108`
- Evidence: Parsing a page with base URL `https://acme.com/` and an `<a href="https://www.acme.com/about">` link produces `links: []`.
- Fix: After the first fetch (and after validating it), use the final response URL as the crawl origin.

**A29. Modern CSS colours are ignored, and "no colours" scores a perfect 25/25**
- Category: Reliability (correctness) · Confidence: **Confirmed**
- Location: `src/lib/extractors/colors.ts:72+, 150-167`, `consistency-score.ts:117`
- Evidence: `rgb(37 99 235 / …)`, `oklch(…)` and shorthand `background: #2563eb url()` all return `[]`. That means Tailwind sites get an empty palette and the maximum colour score.
- Fix: Parse with `culori`, and give missing data a neutral score.

**A30. Logo URL isn't resolved or scheme-checked**
- Category: Reliability / Security · Confidence: **Confirmed**
- Location: `src/lib/extractors/logo.ts:55-110`; rendered in `results-dashboard.tsx:96,218,230,245`, `compare/page.tsx:177`, `report/[slug]/page.tsx:81`
- Issue:
  - Relative paths such as `/assets/logo.svg` resolve against BrandLens instead of the crawled site, so the logo breaks.
  - Attacker-chosen image URLs leak viewers' IPs.
  - `javascript:` is neutralised by React 19.
- Fix: `new URL(raw, page.url)` and allow `https:` only. Optionally proxy the image.

## Release recommendation: **Do not ship**

A public deployment today exposes:
- a server-side browser and fetcher that can be steered into internal networks (A1–A3), with results readable through the public report;
- a stored XSS that fires from a shared link (A4);
- a rate limit that can be bypassed in front of paid LLM calls (A5);
- a start command that can silently drop production data (A6).

The jobs also hang or die in several realistic cases (A7–A9, A12), and a common robots.txt pattern breaks analysis entirely (A10). The quick wins and step 1 of the plan are small, contained changes. Once steps 1–2 are done, the app moves to **Ship with known risks**.

# Addendum: second-pass gap audit (Fable 5.1)

This pass looked only for issues the first audit missed. Before adding them here I independently re-checked the key claims:
- `pnpm audit --prod` → 2 critical / 26 high.
- `prisma/migrations/migration_lock.toml` → `provider = "sqlite"`.
- `pnpm lint` → exit 1.
- `tsc --noEmit` → clean.

## HIGH
- **G1 — Next.js 16.1.6 has public critical and high advisories.** Two critical: RCE in the Image Optimization API via AVIF (GHSA-2xp9-vwfh-vxw4) and a Windows-only RCE. The high ones include an RSC DoS (GHSA-q4gf-8mx6-v5v3, GHSA-8h8q-6873-q5fj), a Server-Action DoS, and SSRF through rewrites. Transitive `undici` is also vulnerable, and `uuid` has a CVE but is never imported. *Fix:* `next@^16.3.3` plus `eslint-config-next`, bump cheerio, remove uuid, and add `pnpm audit --audit-level high` to CI. **Confirmed.**
- **G2 — Node 20 has been past end-of-life since 2026-04-30.** It is pinned in `.node-version`, `nixpacks.toml` and `engines` (`>=20.0.0`, while next needs `>=20.9`). The README still says 18+. *Fix:* Node 22 LTS everywhere. **High Confidence.**
- **G3 — The committed migration history is SQLite while the datasource is Postgres.** `migrate deploy` fails with P3019. That makes `db push --accept-data-loss` (A6) the only working path, so A6 first needs a baseline: regenerate `0000_init` with `migrate diff`, then `migrate resolve --applied` on prod. **Confirmed.**

## MEDIUM
- **G4 — No security headers.** There is no CSP, no frame-ancestors or X-Frame-Options, no HSTS, no Referrer-Policy and no Permissions-Policy, and `X-Powered-By: Next.js` is sent. That means no defence in depth for the XSS in A4, and the Regenerate and Export buttons can be clickjacked. *Fix:* `headers()` plus a nonce CSP in `next.config.ts`, and `poweredByHeader: false`. **Confirmed.**
- **G5 — The shareable public report feature is dead.** Nothing sets `isPublic` except the unauthenticated `publish` route, nothing links to `/report/[slug]`, and the demo slug returns 404. `publicViews` goes up on every fetch. Decide whether to keep the feature (rebuild it with a creator token, a share button and server-rendered metadata) or remove it. **Confirmed.**
- **G6 — On the demo report, "Compare Brands" and "Regenerate" are broken.** Only the PDF route special-cases `DEMO_ID`. *Fix:* a shared `getReportOrDemo()`, and hide Regenerate on the demo. **Confirmed.**
- **G7 — The consistency score gives full marks when data is missing.** Every dimension returns its maximum, so a one-page crawl that extracts nothing scores **100/A**, and the minimum-score floors inflate the rest. This goes beyond A29. *Fix:* score such dimensions as "insufficient data", require at least 3 pages, and remove the floors. **Confirmed.**
- **G8 — PDFs garble non-Latin text and emoji without any error.** The PDF uses the built-in Helvetica font and never registers another (e.g. 東京 → `q ¬ n`, 🚀 → `=€`). Page numbers and the table of contents are hardcoded, and overflow pages have no footer. *Fix:* bundle and register Noto fonts, and render the footer as a fixed element that prints the real page number. **Confirmed** (rendered).
- **G9 — Brandfetch data is always labelled "Verified" at 100% confidence, even for unclaimed brands.** `accent`-type colours become `primary`, so reports end up with several primaries. 3-digit hex values produce `RGB: NaN`. *Fix:* only use `verified` when the brand is claimed, map colour types one-to-one, and validate hex. **Confirmed.**

## LOW
- **G10** The exports drop same-role colours and emit duplicate CSS variables. They also build Google Fonts URLs for fonts that aren't on Google Fonts.
- **G11** Any website can submit a plain-text form that is accepted as JSON by `analyze` and `regenerate`. That spends the visitor's quota and LLM budget without their knowledge. *Fix:* require `Content-Type: application/json` and a same-origin `Origin`/`Sec-Fetch-Site`.
- **G12** Cache semantics are unclear:
  - The `cached` flag never reaches the UI, so reports up to 24h old are served without saying so.
  - `www.` and the bare domain are cached as separate entries.
  - The rate limit resets at UTC midnight, but the message says "tomorrow".
- **G13** There is dead code and there are dead dependencies:
  - Files with no importers: `src/data/mockData.ts`, `src/data/demo-report.ts`.
  - Leftover flags: `USE_MOCK_DATA`, `SKIP_AI_INSIGHTS`.
  - Unused dependencies: `uuid`, `dotenv`, `@types/uuid`, `@types/cheerio`.
  - Schema leftovers: the `EmailSubscriber` model, the email fields, and a duplicate slug index.
  - `.railwayignore` gaps.
- **G14** Lint reports 25 errors, not 1. Two are set-state-in-effect errors (`analyze/[id]:80`, `compare:41`). Next 16's `next build` doesn't run ESLint, so production builds still succeed.
- **G15** No per-route metadata, robots or sitemap, and no error or not-found pages. Every page is a Client Component, and report pages have no `noindex`.
- **G16** The Anthropic client falls back to the SDK defaults: a 10-minute timeout with 2 retries, on each of 4 sequential calls, so a stalled API can hold a job for over an hour. A new client is also created for every call.
- **G19** There is no privacy or retention policy. Crawled phone numbers and addresses are stored forever, and there's no way to request removal. The UA contact URL `brandlens.app` needs to be verified as actually owned.
